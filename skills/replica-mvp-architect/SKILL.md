# Replica MVP Architect & Council

## 1. Recon -> Architect -> Build (Replica Pattern)
1. **Recon**: break down the reference product/feature into core user flows, data entities, API boundaries, and non-essential fluff to cut for v1.
2. **Architect**: define the minimal tech stack, database schema, and vertical slice milestones (end-to-end working MVP first).
3. **Build**: implement one vertical slice at a time with working tests/smoke checks before expanding scope.

## 2. LLM Council Stress-Test (Anti-Sycophancy)
When validating an important architecture, startup idea, or strategic plan, evaluate it from 5 distinct perspectives before locking the decision:
- **Contrarian**: what will break, fail, or get rejected by users?
- **First Principles**: which assumptions are unverified?
- **Expansionist**: where is the 10x leverage or simpler high-impact angle?
- **Outsider**: how does this look to a non-expert or different industry?
- **Executor**: what is the concrete Monday-morning step 1?
Synthesize into a clear final decision and action plan.
